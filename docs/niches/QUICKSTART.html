Cook Lab · model hand-off

Tissue neighbourhoods from an H&E slide

Give it a whole-slide H&E image; it returns a four-class tissue map — epithelium, immune, stroma, acellular — learned from Xenium spatial transcriptomics. No spatial data needed to run it.

predict_niches.py · 4 files, 70 KB trained on 8 HGSC whole tumours snersesian@ohri.ca

What you get

four classes, with their measured accuracy

Each class comes from Xenium-derived 50 µm neighbourhoods. AUC is measured leave-one-tumour-out — every score is from a model that had never seen that tumour.

epitheliumsecretory tumour epithelium, all secretory niches merged AUC 0.911 · worst 0.845
immuneimmune-rich neighbourhood AUC 0.923 · worst 0.804
stromafibroblast, vascular, mesothelial AUC 0.869 · worst 0.626
acellularnecrosis, dense ECM, mucin AUC 0.866 · worst 0.814

Epithelium and immune are the dependable classes. Stroma is strong on average but falls to 0.626 on one unusual tumour, and 17% of true stroma gets labelled immune — both are non-epithelial cellular tissue, so they are genuinely similar under the microscope. Treat stroma and acellular as regional tendencies rather than firm calls.

Why the epithelial niches are merged into one

a deliberate result, not a shortcut

The individual secretory niches encode a polarisation axis (SecA → transitioning → SecB) that matters clinically. We tried hard to read that axis from morphology and it is not recoverable: per-class F1 landed at 0.03–0.17 and did not budge when we gave it fourteen times more data. A separate continuous SecB model reached only AUC 0.65–0.78, with no way to tell in advance which tumours it would handle.

Merged into a single epithelium class, the compartment is read reliably at AUC 0.911. That trade is the whole point of this model — it gives you the part that holds up.

Setup

about fifteen minutes, once

Get access to the feature extractor

The model sits on top of UNI2-h, a pathology vision model that is access-gated. Request it at huggingface.co/MahmoodLab/UNI2-h using your institutional email — approval is manual but not slow.

Install the dependencies

pip install "timm>=0.9.8" huggingface_hub torch tifffile zarr \
            scikit-image scipy joblib pillow matplotlib

Log in and cache the weights

Paste a read token from your Hugging Face settings. Note the command name — recent versions renamed it, so huggingface-cli login will not work.

hf auth login

The first run downloads about 2.5 GB and caches it.

Run one slide and look at it

python predict_niches.py SLIDE.ome.tif --mpp 0.2201 --out results_slide1

Open results_slide1/niche_maps.png before running a batch. Roughly an hour for a 60 mm² section (~17 tiles/sec on an Apple M3 Max, faster on a CUDA GPU).

Set --mpp to your own scanner's value. It is the microns-per-pixel of your level-0 image, and there is no default on purpose.

The model reasons in microns — a 32 µm grid with 112 µm windows. If the value is wrong, every tile is physically the wrong size and results quietly degrade with no error. Read it from your slide metadata. Ours was 0.2201; yours may differ.

What it writes

four files per slide
tiles_niches.csv
One row per 32 µm tile: position, a probability per class (p_epithelium …), the most likely class, and per-class calls.
niche_maps_250um.npz
A 250 µm probability grid per class, plus tile counts. NaN off tissue. This is the one to use for analysis.
niche_maps.png
H&E, a most-likely-niche map, and one probability map per class. Your first check on every slide.
summary.json
Tile count, tissue area, and the class mix the model saw.

Two things about interpreting it

both matter more than they sound

Use the probabilities, and set thresholds per slide. Across our eight tumours epithelium content ranged from 4.5% to 98.4%. On the 4.5% tumour the model ranked tiles correctly (AUC 0.935) but a fixed cutoff gave a precision of 0.23 — not because the model was wrong, but because any fixed threshold fails on a rare class. The script already writes per-slide top-quantile calls (call_*); prefer the continuous p_* columns wherever your analysis allows.

Work at 250 µm, not per tile. We swept this properly: finer is noisy, coarser smooths real structure away. Per-tile agreement with truth was substantially worse than per-region agreement.

For stacking serial sections

what the model does not do for you

Tile coordinates are in each slide's own pixel space, so consecutive sections are not aligned to one another — you will need to register them yourself. The 250 µm grids are reasonable registration targets, being smooth and tissue-shaped.

One suggestion worth the effort: check a single section per tissue block against something orthogonal — even a pathologist's eye on the overlay. Reliability is a property of the tumour, and all sections from one block share that tumour, so one check tells you about the whole stack.

Limits, stated plainly

please read before publishing anything from it
  • HGSC only, post-Xenium H&E, a single scanner at 0.2201 µm/px. Other tumour types, stains or scanners are extrapolation. Stain normalisation is applied automatically and helps, but is not a guarantee.
  • Tissue is found from the image alone — dark and saturated pixels, with small fragments dropped. Verified to keep stained tissue and reject grey ink marks and pale background. Not tested against pen marks, large bubbles, or heavy artefact.
  • This is a compartment map, not a cell-state map. It will not tell you about SecB.
  • No per-slide reliability score. All eight tumours reached epithelium AUC ≥ 0.845, so the risk is low, but a new slide cannot be certified in advance.
  • Not yet run on a slide from another scanner. The full pipeline was tested end to end on a synthetic slide, and the image-reading code is unchanged from the version that processed 260,000 real tiles — but you will be the first to run it on your material. Start with one slide.
